# 视觉审查清单

## 快速审查

- 三秒内能否识别主题？
- 是否只有一个主导视觉？
- 核心信息和 CTA 是否清楚？
- 是否使用精确品牌色和正确字体角色？
- 是否落入泛化 AI 俗套？

## Gate A：内容正确性

- [ ] 无编造产品能力、客户、指标、数据或“领先”措辞。
- [ ] 标题、数据、来源、日期、CTA 与材料一致。
- [ ] 图形不暗示未经确认的架构。
- [ ] 装饰图表不会被误认为真实数据。

## Gate B：信息与构图

- [ ] 只有一个明确主导视觉。
- [ ] 阅读路径连续。
- [ ] 相关内容成组，不相关内容有分隔。
- [ ] 对齐依据可解释。
- [ ] 留白承担聚焦、分隔或节奏功能。
- [ ] 对比足够果断。
- [ ] 规则破坏有明确沟通收益。

## Gate C：品牌一致性

- [ ] 色值精确：在 `strict` 模式只用 [brand-system.md](brand-system.md) 中已确认的五个品牌 token（`AB_BLUE_1` `AB_BLUE_2` `AB_BLUE_3` `AB_BLUE_4` `AB_CHARCOAL`；上游 `tokens/archebase.tokens.json`）。在 `guided`/`creative` 模式，非 token 颜色必须标为渠道/活动扩展色，不能冒充官方品牌色。白/浅色表面是应用默认，不是品牌 token，不得计入本门。
- [ ] 字体角色符合 brand-system.md 的已确认字样与字重，未自造字样；模式允许的生产替代和待确认事项由 `archebase-vi-guide` 判定。
- [ ] 白底小字未使用低对比辅助色。
- [ ] 在 `strict`/`guided` 模式下，检查是否使用了至少一个适合内容的本 Skill 自定母题；这是设计质量项，不是 VI 原文条款，也不替代官方证据。`creative` 模式允许有意偏离，但应记录偏离理由。
- [ ] Logo 未变形、改色或添加效果；官方资产、变体和渲染规则由 `archebase-vi-guide` 负责。

## Gate D：生产可靠性

- [ ] 在最终尺寸检查正文、图注和细线。
- [ ] 图像裁切未遮挡关键对象。
- [ ] 尺寸、格式、色彩模式、安全边距明确。
- [ ] 手机缩略图不依赖微小细节。
- [ ] 渠道不支持的布局能力已替换。

## Gate E：无障碍

- [ ] 正文对比度按项目已声明并记录的 WCAG 版本与等级实测；等级必须逐项目声明，不得默认假定为 AA（见 [accessibility.md](accessibility.md)）。
- [ ] 关键意义不只靠颜色。
- [ ] 语义结构、替代文本与字幕齐备；关键文案是真实文本而非图片内文字。

## Gate F：来源与素材记录

- [ ] 任何检索候选均已通过硬约束过滤，并记录来源、采用理由或淘汰理由。
- [ ] 每个素材与字体都记录了来源与用途；交付物中不出现无法追溯的素材。第三方素材在内部默认按已获授权处理，本 Skill 不维护许可台账；对外发布前由发布方确认授权。

## 修订优先级

**Gate（任一失败即停止交付；Gate 之间不排序）：** ① 事实与用户内容 ② 品牌硬边界（Logo 完整性、公开名称 `ArcheBase`、权利/隐私、禁用项）③ 可读性 / 渠道能力 / 无障碍。

**Gate 全部通过后再按偏好取舍（按此顺序）：** 信息层级 → 构图与网格 → 品牌视觉偏好（色彩角色、字体角色、母题）→ 风格 → 装饰。

与 [SKILL.md](../SKILL.md) 质量门 1-6 的对应：1=Gate A、2=Gate B、3=Gate C、4=Gate D、5=Gate E、6=Gate F；两份清单的 Gate 集合相同，不得只过其中一份。
