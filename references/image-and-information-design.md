# 图像与信息设计

本文件将 Rune Pettersson《Information Design 3 — Image Design》的方法转化为 ArcheBase 的执行规则。它是信息设计参考，不是 VI 原始条文。

## 先定义图像任务

每张图先回答：服务谁、解释什么、在哪个媒介被看见、希望读者采取什么行动。指定一个主职能：说明、比较、定位、展示过程、提供证据、建立尺度、强化记忆或吸引注意。不能说明功能的图片删除。

- 用摄影记录真实对象、现场、设备、材料和事件证据。
- 用图示表达系统、流程、输入输出、层级、连接和状态变化。
- 用技术插图表达内部结构、不可直接观察的机制和尺度转换。
- 用数据图表达证据和比较；不要用氛围照片替代数据关系。
- 可混用多种类型，但必须定义角色分工和统一视觉语法。

## 清晰度与可读性

- 保持明确图底关系、足够尺寸和对比度；按最终观看距离检查。
- 流程图统一线宽、箭头、节点、符号和标签；连线必须明确接入对象。
- 限制线型、字体、纹理和颜色变量；避免伪三维、过度阴影、低对比灰阶和密集装饰。
- 复杂过程拆成序列、分层或连续页面；不要把所有步骤压进一张图。
- 颜色不是唯一编码渠道，同时提供文字、形状、位置、图案、线型或图标。

## 图文整合、数据图与真实性

- 信息图片配图注：说明图中是什么、应关注什么、与结论有什么关系；图注不是“这是一张图”。
- 图像与正文靠近；图内文字短、粗、清晰，长解释放在图注或正文；复杂图表提供阅读顺序、图例、单位和来源。
- 图表先定义要支持的判断，再选类型；比较优先使用位置或长度，少用面积、体积、透视和三维效果。
- 摄影不是天然客观；机位、裁切、人物姿态和背景都会改变解释。
- 生成图不得暗示真实设备、客户、现场、实验结果或产品能力；概念图必须明确标注。
- 记录原图、裁切、调色、合成、编辑目的、来源、许可范围和版本。

## ArcheBase 默认

真实设备和物理环境用于证明现实；图示用于解释关系；数据图用于展示证据；插画用于解释不可见结构。统一摄影视角、插画线条、图表编码、图注和来源标记，避免发光大脑、伪仪表盘、随机电路板和无意义粒子。

## 交付检查

- [ ] 能用一句话说明图像主信息和主职能。
- [ ] 实际尺寸下主体、线条、符号和标签可辨认。
- [ ] 图注、替代文本、来源、授权和编辑记录齐全。
- [ ] 复杂关系已分层或序列化。
- [ ] 图片与正文、标题和 CTA 没有事实冲突。
- [ ] 已按目标受众、文化、语言、设备、距离和光照检查。
