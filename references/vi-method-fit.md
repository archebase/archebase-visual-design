# VI Guide → Visual Design 方法适配

## 目的

本文件把官方《智域基石 VI 基础》PDF及其已验证页面记录中的**视觉判断**转译为 `archebase-visual-design` 可执行的方法。它不复制 VI Guide 的品牌事实、资产清单、Logo resolver、渠道硬规则或发布门禁；这些仍由 `archebase-vi-guide` 权威负责。

来源身份：`archebase/archebase-vi-guide`，tag `v3.5.4`，commit `918d0ec8f05f775d1f34370e0c38fc796da8b83b`；官方 PDF SHA-256 `80680405ee05512878f5ecadc50cf32975d5a5d18c81b1ea17bcc8ad681493cb`。

## PDF 证据盘点

| Guide 页面 | 可转译的设计方法 | 证据边界 |
|---|---|---|
| pp.1–5 Logo forms | 识别资产应作为不可变系统元素处理；构图先给资产留出真实上下文和对比度 | 不能从页面推断安全区、最小尺寸或自行重绘方式 |
| pp.6–21 typography specimens | 用有限字体家族建立完整层级；中英文、标题、数字、正文和标签保持角色分工 | 具体生产文件、CSS 字重、授权和回退栈仍由 `vi-guide` 核验 |
| p.22 core identity | 正式身份材料围绕一个核心身份组织，不把 Logo 当装饰贴纸 | 不推断未记录的 lockup 参数 |
| pp.23–25 auxiliary identities | 组合和方向是系统变量，必须从批准变体中选择，不临时拼装 | 没有完整机器可读的选择矩阵，不推断普遍渠道规则 |
| p.26 type | 字体角色先于风格变化；通过字重、尺度、位置和留白建立层级 | 不把页面样本当作生产字体文件或许可证证明 |
| p.27 phrase/context | 品牌短语是按 brief 调用的语义资产，不是每件物料必放的装饰 | 不从短语推导客户、产品或能力宣称 |

| pp.30–32 neutrals | 中性色可形成技术场、阅读表面和文字层级；先建立中性结构再加入品牌蓝 | 不能从示例推断通用 CSS alpha、透明度或所有渠道实现 |
| pp.33–36 naming/application | 正式名称和应用语境属于系统一致性的一部分；名称、Logo和构图一起审查 | 示例不是普遍版式模板；公开名称以当前批准值为准 |

## 适合 Visual Design 的六条方法

### 1. 先建立中性结构，再注入品牌识别

先用中性场、黑白层级、网格、尺度和留白解决阅读顺序，再用品牌蓝建立识别和重点。颜色不能替代主次关系；主蓝也不能被平均撒在所有元素上。

### 2. 一个主导场、一个结构蓝、一个有意义的强调

默认减少同时竞争的视觉变量：一个主导背景/场域，一个承担结构的蓝色，一个承担信号或流向的强调。其他层级优先通过明度、面积、位置、密度、字重和留白建立。该方法是对 Guide visual grammar 的设计转译，不新增品牌色事实。

### 3. 证据优先于装饰

每个节点、连线、模块边界、数据图、照片裁切和纹理都要回答“解释了什么”。优先使用真实物理世界、可追溯数据、系统边界、标注模块和转换关系；删除随机节点、发光、装饰性渐变、伪仪表盘和无语义纹理。

### 4. 用叙事类型选择构图

先判断物料属于哪一种主叙事，再选构图：

- **系统陈述**：稳定网格、明确边界和模块关系。
- **证据陈述**：结论先行，数据、图表和来源紧随其后。
- **转换流程**：从物理输入到组织、验证和行动，使用方向、阶段和节点。
- **比较/决策**：保持共同轴线，用位置、长度、明度或结构差异支持比较。
- **图像主导**：让真实设备/环境承担主体，文字进入安静区域并保留证据和来源。

### 5. 结论先于元数据，层级不超过必要复杂度

标题先说判断，来源、时间、单位和方法随后提供支撑。strict 方向默认不超过三层信息层级；guided/creative 可按渠道调整，但不能让元数据夺走主判断。

### 6. 把视觉板当作案例，不当作模板

从 pp.37–46 研究“为什么这样裁切、留白、配图和排列”，提取可迁移的关系：密度、比例、尺度、图底、上下文和证据位置。不要复制某一页的外观，也不要在未完成人工渲染审查前把视觉推断写成品牌硬规则。

## 模式适配

| 模式 | Visual Design 方法强度 | 颜色与构图边界 |
|---|---|---|
| `strict` | 完整采用六条方法；以证据、结构、层级和资产上下文为先 | 遵守已确认 token、资产和 Guide 证据；未确认项进入 `待确认` |
| `guided` | 采用方法作为默认建议；软偏离需说明 | 可按渠道做构图和表达调整；不冒充官方 token 或 strict 通过 |
| `creative` | 保留证据、权利、事实和资产完整性；允许更强的表达探索 | 可改变裁切、节奏、纹理、隐喻和活动色，但记录偏离与收益 |
| `off` | 不调用 ArcheBase 方法作为品牌判断 | 不输出 VI 合规或 ArcheBase 发布 verdict |

## 不应从 VI Guide 吸收为通用方法的内容

以下仍留在 `archebase-vi-guide`：

- 官方 Logo 文件、变体选择、渲染器和完整性校验。
- 品牌 token、Guide p.28 比例、无色彩中性色阶和字体证据。
- 当前公开名称、命名限制、组合锁定和渠道应用批准。
- route playbook、渠道安全区、claims/rights、export/QA 与 release verdict。
- Guide 中未确认项目的数值、CSS 实现、最小尺寸和色彩转换。

## 设计检查

交付 Visual Design 方案前，检查：

- 是否只有一个主要受众判断？
- 去掉颜色、Logo和图片后，结构是否仍然成立？
- 是否有一个主导场域、一个结构轴和一个有意义的强调？
- 每个图形元素是否解释事实、关系、过程、尺度或证据？
- 标题是否先给结论，来源和元数据是否足够但不夺主？
- 是否按真实裁切、尺寸、距离和缩略图检查？
- 若使用视觉板，是否记录为案例推断而非官方模板？
- 是否把最终品牌 verdict 留给 `archebase-vi-guide`？
